**Audit:** I gave the draft to a no-context n8n builder, a bookkeeping person and a skeptical tester. They had 19 guesses between them. Your answers settled 8, and 11 are now written down as assumptions, marked **(assumed)**. The four that matter most:
1. **Paid checkbox:** you tick it after paying. The Monday summary only lists unticked rows. Without it, it can't know what's still open.
2. **Google login on self-hosted n8n:** your Google Cloud OAuth app has to be set to "In production", not "Testing". In Testing, Google cuts the connection every 7 days and the flow stops silently. This is the most common way these setups die.
3. **Missing due date:** if the PDF only says "payable within 14 days", the due date is worked out from the invoice date. If there's nothing at all, the row is flagged and the field stays empty.
4. **Monday summary:** sent Mondays at 07:00 Berlin time, and also sent when nothing is due ("nothing due this week"), so you notice if it ever stops arriving.

v1:

- Monday Telegram summary of what is due (decided)
Out: backlog import of older invoices (decided: from go-live on only), payments (decided),

## 3. Flow
Trigger: Gmail, polling every 15 min (assumed), only mails from senders on the supplier list (D1).
1. For each new mail from a listed supplier that has a PDF attached and is not labelled
   `Invoice/processed`:
2. An AI step reads the PDF and returns JSON (schema in §5). (decided: AI)
3. Duplicate check (§4) against the sheet AND against other items in the same run.
4. Save the PDF to `<advisor folder>/<YYYY-MM>/YYYY-MM-DD_<supplier>_<gross>.pdf`
   Date and month = invoice date from the PDF. (decided)
5. Append a row to the sheet.
6. If any flag rule applies (§4): set Flag + reason and send a Telegram message. (decided)
7. Label the mail `Invoice/processed`. (assumed)

Monday summary: every Monday 07:00 Europe/Berlin (assumed). Telegram message listing the
unpaid rows (Paid unticked) that are (a) overdue, (b) due Mon-Sun this week, (c) flagged
"no due date". Each line: supplier, invoice no., gross, due date. Plus the total for the week
and the time of the last successful intake run. If nothing is due: "Nothing due this week."
(decided: summary, assumed: format/time)
The summary is information only: no payment links, no buttons that trigger anything. (decided)

## 4. Rules & edge cases
Duplicates (decided: no dupes; method assumed):
- Key = supplier short name + invoice number. Key already in the sheet with the same gross
  amount → skip: no file, no row, label the mail `Invoice/duplicate`.
- Same key, different amount → treat as a correction: save + new row, flagged "possible
  correction of row X".
- Invoice number missing → fallback key supplier + invoice date + gross, and flag the row.
- Two mails with the same invoice in one polling run → only the first is processed.
Flags (Flag column + Telegram message each):
- gross > 500.00 EUR (decided)
- AI confidence < 0.8, or the AI's supplier name doesn't match the sender list (assumed)
- negative amount (credit note) or currency ≠ EUR (assumed)
- no due date found (assumed; if payment terms in days are stated, due date = invoice date + days)
- more than one PDF in the mail, and it's unclear which one is the invoice: process the one the
  AI marks as the invoice, flag the row (assumed)
- the AI says the PDF isn't an invoice → no row, mail labelled `Invoice/ignored`, Telegram note
  (assumed)
Supplier mail without a PDF (e.g. download link only): label `Invoice/needs-manual`, Telegram
note, nothing else. (assumed)
Filenames (decided format): gross as `1234.56`, no currency sign; supplier = short name from
D1; if the name already exists in the folder, append `_2`, `_3`. (assumed)
Folders: `YYYY-MM` directly inside the existing advisor folder, created if missing. (decided
per month; naming assumed)

## 5. Data contract
AI output (JSON, temperature 0):
{ "is_invoice": bool, "supplier_name": str, "invoice_number": str|null,
  "invoice_date": "YYYY-MM-DD", "due_date": "YYYY-MM-DD"|null, "payment_terms_days": int|null,
  "gross_amount": number, "currency": "EUR", "confidence": 0-1 }
Sheet: keep the owner's existing columns (date, supplier, invoice no., gross, due date: read the
real header row and map to it, don't rename). Add on the right: Drive link, Flag, Flag reason,
Paid (checkbox, owner ticks by hand), Processed at. (assumed)
Dates as real sheet dates, amounts as numbers, not text. (assumed)

## 6. Tech & constraints
- Owner's existing self-hosted n8n. No new platform, no paid SaaS. (decided)
- AI: OpenAI or Anthropic API key, whichever the owner has. Cost well under 1 EUR/month. (decided:
  AI; provider assumed)
- Credentials in the n8n credential store only. Never in workflow notes, code nodes or this brief.
- Google OAuth client must be published ("In production"), or refresh tokens expire after 7 days.
- Telegram: bot token + owner's chat ID, provided by the owner.

## 7. Inputs the owner provides
D1 supplier list: sender address(es) → short name (5 entries) · the advisor folder link · the
sheet link · last month's invoice mails (test set; the hand-typed rows are the expected results).

## 8. Done criteria

  (date, supplier, invoice no., gross, due date) for every invoice, or the row is flagged.
- Given the same invoice mailed twice, exactly one file and one row exist.
- Given a 600 EUR invoice, a flag and a Telegram message appear within 20 min.
- Given an expired or wrong credential, a Telegram failure alert arrives. No mail gets labelled
  processed without its row.
- Monday 07:00 the summary arrives and matches the sheet.
- The workflows contain no payment, bank or outgoing-mail nodes.
