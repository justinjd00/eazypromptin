That's a very doable setup. Five suppliers and PDFs in Gmail is about the easiest case there is. Here's how I'd build it in n8n.

## What it does

Supplier email arrives → PDF gets read → invoice data lands in a spreadsheet → PDF is filed in a clean folder structure → email gets labeled as done → you get pinged before anything is due.

## Step 0: Gmail prep (5 minutes, outside n8n)

Create a Gmail filter that matches your 5 suppliers:

```
from:(billing@supplier1.com OR invoices@supplier2.de OR ...) has:attachment filename:pdf
```

Have it apply the label `Invoices/New`. Also create `Invoices/Done` and `Invoices/Check`. This keeps n8n from looking at your whole inbox, and gives you a visual queue.

## Workflow 1: Process incoming invoices

1. **Gmail Trigger**
   Poll every 15 minutes, filter on label `Invoices/New`, turn on **Download Attachments**.

2. **Split Out** (or a small Code node)
   One item per attachment, and drop anything that isn't `application/pdf`. Some suppliers attach T&Cs or a logo, so don't skip this.

3. **Extract From File** → operation *PDF*
   This gives you the text layer. Invoices from billing systems almost always have real text. If one supplier sends scans, you'll get empty text back; for that one, send the PDF straight to a vision-capable model instead.

4. **Information Extractor** (AI node) with an LLM attached
   Give it a fixed schema:
   `supplier, invoice_number, invoice_date, due_date, net_amount, vat_amount, gross_amount, currency, iban`
   Two things to put in the instructions:
   - "Output amounts as plain numbers with a dot as decimal separator." European invoices write `1.234,56`, and if you don't say this you'll eventually get 1.23 instead of 1234.56.
   - "Dates as YYYY-MM-DD."
   For the model: Mistral (EU-based) or OpenAI/Anthropic with a DPA both work fine. If you want nothing leaving your server, Ollama with a small model handles this job well because the text is short and structured.

5. **Dedupe check**
   Look up `supplier + invoice_number` in your sheet. Suppliers resend invoices and reminders with the same PDF, and you don't want to log them twice.

6. **Sanity check (IF node)**
   If `gross_amount` or `due_date` is missing, or `net + vat` doesn't roughly equal `gross`, route to the "check" branch: label the email `Invoices/Check` and send yourself a message. Otherwise continue.

7. **Upload the PDF** (Google Drive, Nextcloud, or just a folder on your server)
   Path like `Invoices/2026/10/2026-10-14_SupplierName_INV-4821.pdf`. Upload the original file unchanged; you're required to keep originals (typically 10 years in Germany, similar elsewhere in the EU).

8. **Google Sheets → Append Row** (or Postgres if you prefer)
   Columns: the extracted fields plus `file_link`, `status = open`, `processed_at`.

9. **Gmail → Add/Remove Labels**
   Remove `Invoices/New`, add `Invoices/Done`.

## Workflow 2: Due-date reminders

- **Schedule Trigger**, daily at 8:00
- Read the sheet, keep rows where `status = open` and `due_date` is within the next 3 days
- Send one summary message (email, Telegram, whatever you use): supplier, amount, due date, link to PDF
- When you've paid, set `status = paid` in the sheet. (Later you could automate that by matching bank transactions, but don't start there.)

## Gotchas worth knowing upfront

- **Gmail OAuth on self-hosted n8n:** you need your own Google Cloud OAuth client, and the redirect URL has to match your n8n's public URL exactly. If your `WEBHOOK_URL` env var isn't set correctly, the credential connect will fail in confusing ways.
- **E-invoices (ZUGFeRD / Factur-X):** some suppliers already send PDFs with an embedded XML file containing all the data. For those, extracting the XML is more reliable than any AI parsing. Worth checking whether any of your 5 do this. In Germany, B2B e-invoicing is becoming mandatory over 2025 to 2028, so this will become more common.
- **Run it on old mail first:** point it at the last 2 to 3 months of invoices with the label applied, then check the sheet against the PDFs. With 5 suppliers you'll spot any parsing quirk quickly.
