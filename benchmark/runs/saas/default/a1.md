Sure. "Manage the jobs" can mean very different apps, though, and the details you give decide whether the agent builds what you actually need. Below is a draft with sensible defaults filled in. After it are a few questions. Answer whichever ones apply and I'll tighten the prompt.

---

**Draft prompt (copy and paste, then edit the parts in [brackets])**

> Build a simple web app for my residential cleaning business to manage cleaning jobs. I'm not a developer, so keep the tech simple, explain how to run it in plain language, and don't add features I didn't ask for.
>
> **Who uses it**
> - Me (owner/admin): full access.
> - My cleaners ([number] people): they log in on their phones and only see the jobs assigned to them.
>
> **What it needs to do (version 1)**
> 1. **Clients:** add, edit and search clients (name, phone, email, address, access notes like gate codes or pets, default price).
> 2. **Jobs:** create a job for a client with date, start time, estimated duration, assigned cleaner(s), price, and notes. Status goes Scheduled → In progress → Done (or Cancelled).
> 3. **Recurring jobs:** set a job to repeat weekly, every 2 weeks, or monthly. I need to be able to change or skip one visit without breaking the whole series.
> 4. **Schedule view:** a day view and a week view that show all jobs, filterable by cleaner.
> 5. **Cleaner view:** a mobile-friendly "My jobs today" list with the address (tap to open in Maps), notes, and a button to mark the job done. Optionally they can add a note or photo.
> 6. **Simple reporting:** for a chosen date range, list completed jobs and total revenue, so I know what to invoice.
>
> **Not in version 1:** online payments, automatic invoicing, client self-booking, SMS reminders. Design the data so these can be added later, but don't build them.
>
> **Tech requirements**
> - Must work well on a phone browser. No native app needed.
> - Choose one simple, well-supported stack and a cheap or free hosting option. Tell me which you chose and why in 2 or 3 sentences before you start coding.
> - Real login for me and each cleaner. Passwords must be stored securely.
> - Client data (addresses, entry codes) is private, so cleaners must not be able to see other cleaners' jobs or the full client list.
>
> **How to work**
> - Before writing code, ask me any questions where you'd otherwise have to guess.
> - Build it in small steps: clients → jobs → schedule view → cleaner view → recurring → reporting. Show me a working version after each step.
> - Include a few realistic sample clients and jobs so I can try it right away.
> - At the end, give me step-by-step instructions for running it and putting it online, written for someone who has never used a terminal.
>
> **Done means:** I can add a client, schedule a recurring biweekly clean, assign it to a cleaner, that cleaner sees it on their phone and marks it done, and it shows up in my revenue report for that week.

**Questions that would change the prompt:**

1. **Is it just you, or do cleaners need their own access?** If it's only you, the app gets much simpler (no logins or permissions for cleaners).
2. **What's the most annoying part of how you handle this today?** Double-bookings, forgetting recurring clients, chasing payments, figuring out who goes where? The prompt should put that first.
3. **What are you using right now?** A spreadsheet, a paper calendar, Google Calendar? If you have a client list in a spreadsheet, the agent should build an import for it.
4. **Is invoicing/payment part of "manage jobs" for you,** or do you handle that separately?
5. **How comfortable are you with running and hosting it yourself?** This decides whether the agent should aim for something like a one-click hosted setup.

One honest note: tools like Jobber, ZenMaid or Housecall Pro already do most of this for roughly $30–70/month. A custom build is worth it if you want something simpler, cheaper long-term, or shaped exactly to how you work. Just be aware that you, or whoever you hire, will be the one maintaining it when something breaks.
