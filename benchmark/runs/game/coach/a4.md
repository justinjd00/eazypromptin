Two of those 6 are worth a look right now:
- **How your friend connects (🔶 A1).** Two PCs in different cities usually can't connect directly; home routers block it. For v1 I picked a free virtual-LAN tool (Tailscale) plus Godot's built-in networking, so you don't need port forwarding and it costs nothing. The network code sits behind one interface, so Steam's relay can replace it later if you go to Steam (that means a $100 Steam app fee and Steam integration work, not v1).
- **C# in Godot.** Fine for PC, but you need the **.NET build** of Godot, and most tutorials and addons are written in GDScript. The agent has to translate them, and the brief says so explicitly.

### BRIEF.md

```markdown
# Dungeon Buddies (working title): Brief

> ✅ decided by you · 🔶 assumed (default, veto anytime) · ❓ open
> Executor audit: 3 readers, 19 guesses → 13 written into rules, 6 high-impact assumptions listed below.

## 0. Top assumptions (read first)
- 🔶 A1 Connection: v1 uses Godot high-level multiplayer over ENet; players connect over a free virtual LAN (Tailscale) by entering the host's address. All networking goes through one transport interface so Steam Networking can replace ENet later without touching gameplay code.
- 🔶 A2 Authority: the host simulates enemies, damage, drops, room state and the RNG seed. Each player moves their own character locally (responsive feel) and the host trusts it. No anti-cheat, because it's for friends.
- 🔶 A3 Unlocks in co-op: each player keeps their own local save; a co-op run uses the host's unlocked upgrade pool; unlocks earned in a run are saved for both players.
- 🔶 A4 Two-player scaling: in co-op, enemy HP ×1.6, same enemy count. Tune at playtests.
- 🔶 A5 Asset pack: Kenney "Tiny Dungeon" (16×16, CC0) once M5 starts. One pack only, never mix styles. Until then, coloured shapes with a fixed palette.
- 🔶 A6 Collaboration: the agent builds; you and your friend play-test after every milestone and give the fun verdict.

## 1. Vision & why
A cute, colourful, funny top-down roguelite for 2 players online. You and a friend fight through a silly dungeon in ~20-minute runs, pick upgrades that combo into ridiculous builds, revive each other, and every run plays differently. Made to play with friends who live in other cities ✅. Steam is a maybe for later ✅, not a v1 goal.
Reference anchors: Soul Knight (aim + shoot + dash, cute pixel dungeon), Enter the Gungeon (gun feel, room-by-room), Ship of Fools (cozy co-op tone).
Anti-goals ✅: no grinding, no permanent stat boosts, no currency farming. A new player and a 50-hour player start a run equally strong. Not dark or punishing.

## 3. Scope
**v1:** online co-op for exactly 2 players ✅ · solo playable 🔶 · 3 floors × ~6 rooms + boss, ~20 min per run ✅ · 12 hand-made room templates shuffled per run ✅ · 6-8 enemy types, 3 bosses ✅ · ~25 combo-able upgrades ✅ · 3-4 starting weapons ✅ · unlock-only meta-progression ✅ · revive system ✅ · Windows build you can send to a friend 🔶
**Later:** random events, shops, secret rooms (variety from places, after builds) ✅ · Steam (store page, invites, relay) · controller support · more floors/biomes · light story
**Out:** fully procedural maps · 3+ players · PvP · permanent stat upgrades · microtransactions

## 4. Experience
**Core loop:** host or join → camp → portal → room: fight → room clears → each player picks 1 of 3 upgrades → next room → floor boss → next floor → after floor 3 boss: win, or both downed: lose → back to camp, unlocks added → new run.
**First two minutes:** host clicks Host, friend joins by address, both spawn in a small camp, walk into the portal together. Room 1: five goofy slimes, both shoot and dash. Room clears, each sees their own 3 upgrade cards. Door opens when both have picked.
**Controls (KB+M ✅):** WASD move · mouse aim · LMB shoot · Space/RMB dash (short i-frames) · E interact/revive · Esc menu.
**Builds = the variety ✅:** upgrades are designed to stack and interact (bouncing + piercing + burning shots = chaos). At least a third of upgrades must change *behaviour*, not just numbers.
**Setting ✅:** classic dungeon played for laughs: slimes, skeletons with bad posture, a dragon boss who just wants a nap. Funny upgrade and enemy names; one intro screen, no other story 🔶.
**Look ✅:** cute, colourful 16×16 pixel art, top-down camera, pixel-perfect scaling. Punchy-but-friendly game feel: small screen shake, hit flash, knockback, particles.
**Audio 🔶:** free CC0 SFX pack in M5, one looping music track.

## 4b. Rules & edge cases
- Downed (HP 0): partner has 10 s to revive by standing next to you holding E for 1.5 s. Revived with 50% HP. Not revived: you respawn at the start of the next room with 50% HP ✅.
- Both downed at the same time, or downed in solo: run over.
- Downed during a boss: the 10 s rule applies; if it runs out you respawn when the boss dies.
- Upgrade picks are per player ✅. Door opens when both have picked, or after 30 s (auto-picks the first card) so nobody gets stuck waiting.
- Health pickups: whoever touches them first. Friendly fire: off.
- Joining player disconnects: host continues solo, enemy scaling drops to solo. Host disconnects: run ends for the joiner with a clear message 🔶.
- No mid-run joining in v1. No pause in co-op (the menu doesn't stop the game); in solo, Esc pauses.
- Room order and room templates come from one seed chosen by the host, so both machines generate the same run.
- Unlocks: beating each boss for the first time, plus finishing a run, unlocks new upgrades/weapons into the pool. Unlocks never raise base stats ✅.
- Save: local JSON (settings + unlocks). A corrupt or missing save starts fresh, never crashes.

## 5. Tech & constraints
- Godot 4, latest stable **.NET build**, C# only, no GDScript ✅. Translate GDScript examples/addons to C# or pick C#-compatible ones.
- PC, Windows first 🔶 (Linux/Mac export later if a friend needs it).
- Networking: Godot high-level multiplayer (MultiplayerSpawner/Synchronizer, RPCs) over ENet behind a transport interface (see A1).
- Tests: gdUnit4 with C# support for pure logic.
- Budget: free/CC0 assets only, no paid tools 🔶.
- Your skill: a bit of Godot. Code should be plain, readable C#, with short comments on networking code, which is the hard part.

## 9. Done criteria (v1)
- Given two Windows PCs in different cities on the virtual LAN, a full 3-floor run can be played start to finish without desync or crash.
- Given 10 runs, no two have the same room order, and builds in at least half of them feel clearly different (your call).
- Must never: give permanent stat boosts; mix art styles; require port forwarding.
- Fun check: after losing, you both want to start another run straight away.

## 11. Agent operating rules
- Work one milestone at a time from MILESTONES.md; each ends in something you can play.
- Ask before: changing the network model, adding a paid or non-CC0 asset, adding an addon/NuGet dependency, anything that breaks save files. Decide reversible things yourself and log them in §7 Decisions.
- Never claim something is fun; list what to try and ask.
- Commit per milestone with a clear message; keep the project building from a clean checkout.
```
