## The one decision that changes everything: "maybe with friends"

This one comes first because it decides how the whole codebase is built. Multiplayer isn't something you bolt on later in Godot. If the game is meant to be co-op, the player, the enemies, damage, loot and spawning all have to be written with networking in mind from day one (who's in charge of the game state, what gets synced, and so on). If you start single-player and add co-op later, you're basically rewriting the core.

So you have three real options:

1. **Single-player only.** Fastest way to something fun. My pick if this is your first proper game.
2. **Single-player first, but built "co-op ready".** Single-player gameplay, but the code is structured so online co-op can be added later without a rewrite. A bit more work up front.
3. **Co-op from the start** (online via Godot's high-level multiplayer, or local couch co-op on one PC, which is *much* easier).

If you "know a bit of Godot", I'd honestly go with 1, or 2 if co-op really matters to you. Online co-op from day one is where hobby projects go to die.

## Questions that pin down the game

**1. What does a run look like?**
- **Roguelike/roguelite** (Hades, Enter the Gungeon, Binding of Isaac): short runs, you die, start over, maybe keep some permanent upgrades.
- **Classic dungeon crawler / ARPG** (Diablo-lite): one character that keeps progressing, persistent loot, deeper floors.
- **Survivors-like** (Vampire Survivors, Brotato): waves of monsters, you auto-attack and pick upgrades, 15 to 30 minute runs.

"Keep getting stronger" fits all three, but they're very different games to build. Survivors-like is by far the smallest scope.

**2. Camera and controls?** Top-down (Zelda/Isaac style) or side-on platformer (Dead Cells)? Keyboard + mouse aiming, or gamepad, or both?

**3. Combat feel?** Real-time action (dodge, aim, attack) or turn-based / grid-based (like Shattered Pixel Dungeon)?

**4. How do you get stronger?** Pick from random upgrades on level-up? Loot and gear with stats? Skill tree? Some mix? And does anything carry over between runs?

**5. Dungeon layout?** Hand-made rooms you design, procedurally generated, or hand-made rooms stitched together randomly (the Isaac approach, good middle ground)?

**6. Art.** Do you have pixel art already, will you draw it, or use free asset packs (itch.io has tons, e.g. 16x16 dungeon tilesets)? This matters because Claude Code can't make the art, so early on it should use placeholder shapes and a defined tile size (16x16 or 32x32) so swapping real sprites in later is painless.

**7. Godot version and language?** Godot 4.x with GDScript I assume? (GDScript is the right call for you, way more examples and fewer headaches than C#.)

**8. What's the goal?** Fun project to learn with, something to play with friends, or something you want to put on Steam/itch eventually?

## What I'd do if you just want a recommendation

If you told me "just pick", I'd go with: **top-down, real-time, roguelite, single-player first but co-op ready, Godot 4 + GDScript, 16x16 pixel art with placeholder shapes at first.** Rooms are hand-made and stitched together randomly, you pick 1 of 3 upgrades on level-up, and gold carries over between runs for small permanent buffs.

And the first thing Claude Code builds should **not** be the whole game. It should be a tiny playable slice: one room, a player who can move and attack, one enemy type that chases you, health, death, restart. If that feels fun, everything else stacks on top. If it doesn't, no amount of features will fix it.
